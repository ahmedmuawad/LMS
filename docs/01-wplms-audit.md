# 01 — تحليل WPLMS: ما الذي نحن بصدد استبداله؟

الهدف من هذا المستند: **جرد دقيق** لكل ما يقدّمه WPLMS، لأن أي ميزة موجودة اليوم في الموقع
الحالي ولا تُغطّى في المنصة الجديدة = مستخدم غاضب يوم الإطلاق.

---

## 1.1 ما هو WPLMS تقنياً

WPLMS ليس قالباً واحداً، بل **منظومة** مكوّنة من:

| المكوّن | الدور |
|---------|------|
| قالب WPLMS | الواجهة والتصميم |
| Vibe Custom Types | ينشئ الـ Custom Post Types والـ Metaboxes |
| Vibe Course Module | منطق الكورسات: التسجيل، التقدّم، التقييم |
| Vibe Shortcodes | الشورت‑كودات |
| WPLMS Dashboard | لوحة تحكم الطالب/المدرّس |
| WPLMS Front End | إنشاء الكورسات من الواجهة الأمامية |
| BuddyPress | البروفايلات، الأنشطة، المجموعات، الرسائل |
| bbPress | المنتديات |
| WooCommerce / EDD | البيع والدفع |
| Elementor / WPBakery | بناء الصفحات |

الإصدار 4 اتجه إلى **Headless WordPress + ReactJS** في الواجهة، مع دعم **PWA**.

> **النتيجة العملية:** الموقع الحالي على الأرجح يعتمد على 10–20 إضافة مترابطة.
> عند الترحيل نحن لا نعيد بناء "قالب"، بل نعيد بناء **منظومة** بالكامل.

## 1.2 جرد المزايا الوظيفية (Feature Inventory)

### أ. إدارة الكورسات
- بنية: كورس ← **أقسام (Sections)** ← **وحدات (Units)** + **اختبارات (Quizzes)** + **واجبات (Assignments)**
- أنواع محتوى الوحدة: فيديو، صوت، مستند، PDF، نص، رابط جلسة مباشرة
- تسلسل إجباري (Drip / فتح تدريجي) ومدة قصوى لإنهاء الكورس
- **حزم كورسات (Bundles)** واشتراكات (أسبوعي/شهري/سنوي) وكورسات منتهية الصلاحية
- قوالب تصميم للكورس (عام / لكل تصنيف / لكل كورس)
- عمليات جماعية: إسناد طلاب دفعة واحدة، رسائل جماعية
- إنشاء الكورس من الواجهة الأمامية بواسطة المدرّس + حفظ كمسودة

### ب. التقييم
- **اختبارات ثابتة** (أسئلة محددة) و**ديناميكية** (سحب عشوائي من بنك الأسئلة)
- **8 أنواع أسئلة:** اختيار من متعدد (إجابة واحدة)، اختيار من متعدد (إجابات متعددة)، مطابقة، ترتيب، قائمة منسدلة، ملء الفراغات، نص قصير، مقالي
- تقييم آلي / يدوي / إعادة تقييم، ونسبة نجاح لكل كورس
- مؤقّت زمني للاختبار، عدد محاولات، أسئلة عشوائية
- بنك أسئلة مع استيراد جماعي
- واجبات برفع ملفات + ملاحظات المدرّس + رفع ملف مُصحّح

### ج. الشهادات والتحفيز
- **مُنشئ شهادات بالسحب والإفلات** مع بيانات الطالب/المدرّس
- **كود تحقق فريد** لكل شهادة + صفحة تحقق عامة
- شارات (Badges) عند نسبة إنجاز معينة
- مشاركة الإنجاز على الشبكات الاجتماعية
- إضافة PDF Certificates لتوليد شهادات PDF

### د. التحقيق المالي (Monetization)
- بيع عبر WooCommerce أو Easy Digital Downloads
- عضويات: PMPro، Restrict Content Pro، WooCommerce Memberships، ARMember، WishlistMember
- بوابات دفع متعددة + دفع يدوي (تحويل بنكي)
- كوبونات وخصومات (من WooCommerce)

### هـ. التواصل والمجتمع
- إشعارات لحظية + **Push Notifications** (عدا Safari iOS)
- رسائل خاصة بين الطالب والمدرّس ("اسأل المدرّس")
- **دردشة مباشرة** مع الأعضاء المتصلين
- إعلانات خاصة بالكورس + مدونة/أخبار المدرّس
- منتديات نقاش على مستوى الوحدة
- الأصدقاء والمتابعة وخلاصة الأنشطة (BuddyPress)

### و. تجربة الطالب
- ملاحظات شخصية وملاحظات المدرّس على الوحدة
- تتبع الأنشطة مصنّفة حسب الكورس/الاختبار/الواجب
- **PWA** بعمل دون اتصال + توليد تطبيق موبايل من لوحة التحكم
- أدلة الأعضاء والمجموعات مع فرز وتصفية

### ز. الإدارة
- نماذج تسجيل مخصّصة بحقول غير محدودة
- تخصيص كل رسائل البريد + جدولة تذكيرات (انتهاء الكورس، الخمول)
- تقارير الأنشطة والتحليلات
- توافق GDPR

### ح. وحدات إضافية (Add-ons)
| الإضافة | الوظيفة |
|---------|---------|
| Vibe Drive | تخزين ملفات ومزامنة Dropbox / Google Drive / S3 |
| Vibe Calendar | تقويم شخصي + مزامنة Google Calendar |
| Vibe KB | قاعدة معرفة |
| Vibe Helpdesk | نظام تذاكر دعم |
| Video Conferencing | Zoom / BigBlueButton / Jitsi |
| Vibe Posts | نشر مقالات من الواجهة الأمامية |
| WPLMS GA | تتبع الأنشطة في Google Analytics |
| Instructor Booking / Batches / Attendance / Learning Paths | إضافات مدفوعة |

## 1.3 بنية البيانات في WPLMS (مهمة جداً للترحيل)

### Custom Post Types
`course` · `unit` · `quiz` · `question` · `testimonial` · `popup`
(بالإضافة إلى `post`, `page`, `product` من WooCommerce)

### Taxonomies
`course-cat` (تصنيفات الكورسات) · `level` (المستوى) · `location`

### أهم الـ Post Meta
| المفتاح | المعنى |
|---------|--------|
| `vibe_course_curriculum` | **مصفوفة مُسلسلة (serialized)** تحوي ترتيب الأقسام والوحدات والاختبارات — هذا هو "العمود الفقري" لبنية الكورس |
| `vibe_course_badge` / `_percentage` / `_title` | إعدادات الشارة |
| `vibe_course_certificate` / `_template` | إعدادات الشهادة |
| `vibe_course_passing_percentage` | نسبة النجاح |
| `vibe_duration` | مدة الكورس |
| `_vibe_forum` / `_vibe_group` | ربط بمنتدى bbPress ومجموعة BuddyPress |
| `vibe_unit_duration_parameter` | مدة الوحدة |
| `vibe_quiz_duration_parameter` | زمن الاختبار |
| `vibe_quiz_course` | الكورس التابع له الاختبار |
| `vibe_assignment_duration_parameter` | مهلة الواجب |
| `{UserID}` (المفتاح = رقم المستخدم) | حالة اشتراك الطالب في الكورس: `0` مشترك لم يبدأ، `1` بدأ |

### أهم الـ User Meta
| المفتاح | المعنى |
|---------|--------|
| `{courseID}` | **توقيت انتهاء** اشتراك المستخدم في الكورس (timestamp) |
| `course_status{courseID}` | `1` ابدأ · `2` أكمل · `3` تحت التقييم · `4` تم التقييم |
| `badges` | مصفوفة مُسلسلة بأرقام الكورسات التي نال شاراتها |
| `certificates` | مصفوفة مُسلسلة بأرقام الكورسات التي نال شهاداتها |

### جداول قاعدة البيانات
- `wp_bp_activity` + `wp_bp_activity_meta` — سجل الأنشطة (مصدر مهم لتاريخ الطالب)
- `wp_bp_course_students` — ربط الطلاب بالكورسات
- `wp_signups` — التسجيلات وأكواد التفعيل
- `wp_users` + `wp_usermeta` — المستخدمون (كلمات المرور بصيغة **phpass** `$P$...`)
- جداول WooCommerce: `wp_posts(shop_order)` أو `wp_wc_orders` (نظام HPOS الحديث) + `wp_woocommerce_order_items`
- نتائج الاختبارات مخزّنة غالباً في **user meta / activity meta** وليس جدولاً منفصلاً منظّماً

> ⚠️ **أهم ملاحظة تقنية:** WPLMS يخزّن منطق الكورس في **مصفوفات PHP مُسلسلة** داخل `wp_postmeta`،
> ونتائج الاختبارات مبعثرة بين `usermeta` و`bp_activity_meta`. هذا يعني أن الترحيل
> **ليس عملية SQL مباشرة** بل يحتاج سكربت PHP يستخدم `unserialize()` ويعيد بناء العلاقات.
> خصّصنا لذلك مرحلة كاملة في [خطة الترحيل](04-migration-plan.md).

## 1.4 لماذا الخروج من WPLMS منطقي

| المشكلة في WPLMS | الحل في Laravel |
|-------------------|-----------------|
| اعتماد على 15+ إضافة، تحديث أي منها قد يكسر الموقع | كود واحد مملوك، اختبارات آلية |
| البيانات في `postmeta` (EAV) → استعلامات بطيئة وتقارير صعبة | جداول علائقية مُفهرسة، تقارير فورية |
| قيود التخصيص: أي سلوك خارج المسار يحتاج hacks | منطق أعمال حر بالكامل |
| الأداء يعتمد على الكاش لإخفاء ضعف الاستعلامات | Octane + استعلامات مصمّمة + كاش اختياري |
| ثغرات WordPress/الإضافات هدف دائم | سطح هجوم أصغر بكثير |
| تكلفة تراخيص سنوية متراكمة للإضافات | تكلفة تطوير لمرة واحدة + بنية تحتية |
| صعوبة بناء تطبيق موبايل حقيقي | REST/JSON API مصمّم من البداية |

## 1.5 مصفوفة "يجب / يُفضّل / لاحقاً"

نستخدم هذه المصفوفة لضبط النطاق ومنع تضخّمه:

### يجب (MVP — بدونها لا نُطلق)
كورسات وأقسام ووحدات · فيديو محمي · اختبارات (6 أنواع أسئلة على الأقل) · واجبات ·
تتبع التقدّم · شهادات + كود تحقق · سلة وشراء ودفع محلي · حساب الطالب ·
لوحة المدرّس · لوحة الإدارة · المدونة · الصفحات الثابتة · البحث · الترحيل الكامل للبيانات · RTL

### يُفضّل (بعد الإطلاق مباشرة)
Page Builder المرئي · الاشتراكات المتكررة · الحزم · الكوبونات المتقدمة · بيع الخدمات بالحجز ·
المنتجات المادية والشحن · الإشعارات اللحظية · التقارير المتقدمة · PWA · نظام العمولات للمدرّسين

### لاحقاً (المرحلة الثالثة)
منتديات · دردشة مباشرة · شبكة اجتماعية (أصدقاء/مجموعات) · تطبيق موبايل أصلي ·
Zoom/BBB · SCORM/xAPI · مسارات تعليمية · حضور وانصراف · تعدّد البائعين (Marketplace) · ذكاء اصطناعي
