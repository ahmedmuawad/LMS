# 12 — سجل القرارات المُقرّة (ADR)

قرارات مُعتمدة من صاحب المشروع. أي تغيير لاحق يحتاج قراراً موثّقاً هنا مع أثره على الجدول.

---

## ADR-001 — مسار الإطلاق: النطاق الكامل
**القرار:** إطلاق واحد بالنطاق الكامل — **25–29 أسبوعاً** (8 مراحل).
**يشمل:** الكورسات + الخدمات + المنتجات + المدونة + Page Builder + المجتمع + التسويق + الترحيل.
**الأثر:** لا إيراد من المنصة الجديدة قبل الإطلاق؛ الموقع الحالي يستمر عاملاً حتى يوم الـ Cutover.
**التخفيف المُلزِم:**
- عرض حيّ (Demo) على Staging في نهاية كل مرحلة — صاحب المشروع يرى تقدّماً ملموساً كل 3–5 أسابيع.
- إقفال نطاق كل مرحلة كتابياً؛ أي إضافة خارج النطاق تدخل "قائمة ما بعد الإطلاق" لا المرحلة الجارية.
- المرحلة 6 (الترحيل) تبدأ تحضيرياً **بالتوازي** من المرحلة 2 (كتابة السكربتات مبكراً).

## ADR-002 — بوابات الدفع: كل البوابات
**القرار:** دعم **كل** البوابات التالية:
| البوابة | السوق | الأولوية |
|---------|-------|---------|
| Paymob (بطاقات · محافظ · فودافون كاش · أقساط) | مصر | P0 |
| Fawry (نقدي بالمنافذ · Fawry Pay) | مصر | P0 |
| Stripe (بطاقات دولية · **اشتراكات متكررة**) | دولي | P0 |
| PayPal | دولي | P1 |
| Tap | الخليج (KNET, Mada, Benefit) | P1 |
| Moyasar | السعودية (Mada) | P1 |
| HyperPay | الخليج (مؤسسي) | P2 |
| تحويل بنكي برفع إيصال + اعتماد يدوي | محلي | P0 |
| محفظة داخلية (رصيد) | محلي | P1 |

**الأثر على الجدول:** المرحلة 3 تصبح **5 أسابيع** بدل 4 (+1 أسبوع).
**بند حَرِج:** إجراءات التعاقد والاعتماد لدى Paymob وFawry وTap وMoyasar تستغرق **2–4 أسابيع** — تبدأ **الآن** في المرحلة 0 بالتوازي مع التطوير، لا في المرحلة 3.
**تصميم:** كل بوابة = بلجن مستقل ينفّذ واجهة `PaymentGateway` + صفحة إعدادات + وضع تجريبي + زر اختبار اتصال + Webhook موقّع ومقاوم للتكرار.
**الاشتراكات المتكررة:** تُدار بمحرك داخلي (دورات، سماح، إعادة محاولة) — Stripe يُستخدم للتحصيل التلقائي، والبوابات المحلية بفوترة يدوية/تذكير دفع.

## ADR-003 — بنية روابط اللغة: العربية بلا بادئة
**القرار:**
```
العربية (افتراضية):   example.com/courses/laravel-basics
الإنجليزية:            example.com/en/courses/laravel-basics
```
**السبب:** يحافظ على **كل الروابط المؤرشفة حالياً في جوجل كما هي** — أقل مخاطرة سيو ممكنة.
**التبعات التنفيذية:**
- Middleware يكتشف اللغة: بادئة `/en` → إنجليزي، غير ذلك → عربي.
- `hreflang` لكل صفحة: `ar` (بلا بادئة) + `en` (بالبادئة) + `x-default` → العربية.
- `canonical` يشير دائماً للرابط بلا بادئة في العربية.
- **الحفاظ على الـ slugs العربية الأصلية** من WordPress حرفياً حيثما وُجدت.
- خرائط موقع منفصلة لكل لغة داخل فهرس واحد.
- `<html lang dir>` يُضبط ديناميكياً.

## ADR-004 — Filament v4 (وليس v5)
**القرار:** البناء على Filament v4 / Livewire 3.
**السبب:** نظام الإضافات على v4 أنضج، وهو أهم أسباب اختيار Filament أصلاً.
**مسار الخروج:** ترقية إلى v5/Livewire 4 بعد الإطلاق واستقرار المنصة.

## ADR-005 — Page Builder بالبلوكات لا Canvas حر
**القرار:** مكتبة **مغلقة من ~25 بلوك**، تخزين JSON، عرض بمكوّنات حقيقية.
**السبب:** Canvas الحر (نموذج Elementor) ينتج صفحات مكسورة في RTL والموبايل، ويستهلك 6+ أسابيع، ويستحيل صيانته.
**قاعدة:** أي بلوك جديد بعد الإطلاق = قرار موثّق، لا طلب عابر.

## ADR-006 — الأداء والسيو بوابة CI لا "تحسين لاحق"
**القرار:** ميزانية الأداء في [وثيقة 06](06-performance-and-seo.md) **تُفرض آلياً في CI**؛ أي PR يكسرها يُرفض.
**السبب:** صاحب المشروع حدّد الأداء والسيو كأولوية أولى؛ الأولوية بلا بوابة آلية تتآكل تحت ضغط المواعيد.

## ADR-007 — ترحيل كلمات المرور بلا إعادة تعيين
**القرار:** Hasher مخصّص يقبل `phpass` و`bcrypt` من WordPress، ويعيد التجزئة إلى bcrypt عند أول دخول ناجح.
**السبب:** إجبار آلاف المستخدمين على إعادة تعيين كلمة المرور = فقدان جزء منهم.

## ADR-008 — الفيديو: Bunny Stream بروابط موقّعة (DRM مؤجّل)
**القرار:** Bunny Stream + روابط موقّعة قصيرة العمر + علامة مائية ديناميكية + كشف المشاهدة المتزامنة.
**DRM الاستوديو (Widevine/FairPlay) مؤجّل** حتى ثبوت قرصنة فعلية تبرّر تكلفته.
