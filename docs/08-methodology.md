# 08 — منهجية العمل ودورة إقفال المرحلة

> هذه هي طريقة العمل المتفق عليها. **لا تُقفل أي مرحلة قبل اجتياز البوابات الخمس.**

---

## 8.1 الدورة (تتكرر في كل مرحلة)

```
┌─────────────────────────────────────────────────────────────┐
│ 1. توثيق    │ نكتب ماذا سنبني بالضبط، وما معايير القبول      │
│ 2. تخطيط    │ نقسّم المرحلة إلى مهام صغيرة قابلة للقياس       │
│ 3. تنفيذ    │ نبني، مع اختبارات مع الكود لا بعده              │
│ 4. مراجعة ذاتية │ نراجع ما نفّذناه مقابل معايير القبول       │
│ 5. مراجعة بعينين مختلفتين:                                   │
│    أ) عين مبرمج آخر  → الكود، الأمان، الأداء، الحالات الحدّية │
│    ب) عين صاحب المشروع → هل تحقّقت القيمة التجارية؟          │
│ 6. سد الثغرات │ ننفّذ ما كشفته المراجعتان                    │
│ 7. إقفال     │ توثيق + تقرير مرحلة + دمج + الانتقال للتالية  │
└─────────────────────────────────────────────────────────────┘
```

## 8.2 البوابات الخمس لإقفال أي مرحلة

| # | البوابة | المعيار |
|---|---------|---------|
| **1** | **الوظيفة** | كل بند في نطاق المرحلة يعمل فعلياً وتم عرضه (Demo) |
| **2** | **الجودة** | تغطية اختبارات ≥ 70% للمنطق الحرج · Larastan نظيف · Pint نظيف · صفر أخطاء في CI |
| **3** | **الأداء** | كل صفحة جديدة داخل ميزانية الأداء (وثيقة 06) · صفر N+1 · Lighthouse ≥ 90 |
| **4** | **السيو والوصولية** | Schema صحيح · عناوين ووصف · hreflang · H1 واحد · RTL سليم · تباين ألوان AA · تنقّل بلوحة المفاتيح |
| **5** | **الأمان والتوثيق** | صلاحيات على كل مسار · تحقق من المدخلات · لا أسرار في الكود · README الموديول مكتوب · الإعدادات موثّقة |

## 8.3 قوائم المراجعة (Checklists)

### أ. مراجعة "بعين مبرمج آخر" (Peer Review)
```
□ هل يوجد N+1 أو استعلام داخل حلقة؟
□ هل كل استعلام ثقيل مفهرس؟ (EXPLAIN)
□ هل العمليات الطويلة في طوابير؟
□ هل هناك منطق أعمال داخل Controller بدل Action/Service؟
□ هل الحالات الحدّية مغطّاة؟ (قيمة صفر · حذف · تزامن · انتهاء صلاحية · شبكة مقطوعة)
□ هل التعامل مع الأخطاء واضح ورسالته مفيدة للمستخدم بالعربية؟
□ هل الصلاحيات مفروضة على مستوى الخادم لا الواجهة فقط؟
□ هل توجد ثغرة IDOR؟ (المستخدم يصل لمورد غيره بتغيير الرقم)
□ هل المدخلات مُتحقَّق منها ومُطهَّرة (XSS/SQLi)؟
□ هل العمليات المالية داخل Transaction؟ وهل هي Idempotent؟
□ هل Webhooks تتحقق من التوقيع وتقاوم التكرار؟
□ هل النصوص كلها مترجمة (لا نص مكتوب مباشرة في الكود)؟
□ هل الواجهة سليمة في RTL وLTR وعلى الموبايل؟
□ هل تمت إضافة اختبارات تفشل لو انكسر السلوك؟
□ هل الكود مفهوم بعد 6 شهور بدون شرح؟
```

### ب. مراجعة "بعين صاحب المشروع" (Product Review)
```
□ هل يستطيع مستخدم حقيقي إنجاز المهمة بلا شرح؟
□ كم نقرة تحتاج المهمة؟ هل يمكن تقليلها؟
□ ماذا يحدث لو أخطأ المستخدم؟ هل الرسالة مفيدة أم تقنية؟
□ هل الشاشة تعمل على شاشة 360px؟ وعلى إنترنت بطيء؟
□ هل النصوص العربية سليمة لغوياً ومهنية؟ (لا ترجمة حرفية)
□ هل يستطيع المدير التحكم في هذا من اللوحة، أم يحتاج مبرمجاً؟
□ هل الميزة تُقاس؟ (أين تقريرها؟)
□ هل تفتح الميزة باب استغلال مالي؟ (خصم مكرر · وصول مجاني · استرداد مزدوج)
□ ما الذي سيسأل عنه الدعم الفني كثيراً بسبب هذه الشاشة؟
□ هل تظهر الميزة في السيو إن كان لها قيمة بحثية؟
```

### ج. قائمة "ما الذي نسيناه؟" (Gap Hunt)
```
□ الحالات الفارغة (Empty states) — ماذا يرى المستخدم قبل وجود بيانات؟
□ حالات التحميل والخطأ لكل طلب
□ الصلاحيات لكل دور على هذه الشاشة (5 أدوار × كل إجراء)
□ الترجمة الإنجليزية موجودة ومراجَعة
□ البريد/الإشعار المرتبط بهذا الحدث موجود ومترجم
□ الإعداد المرتبط موجود في لوحة التحكم
□ التقرير المرتبط موجود
□ سجل التدقيق يسجّل هذا الإجراء
□ الترحيل من WordPress يغطي هذا الكيان
□ الـ API له نقطة نهاية مقابلة (للموبايل مستقبلاً)
□ الاختبار الآلي موجود
□ التوثيق مكتوب
```

## 8.4 تعريف "منتهي" (Definition of Done) لأي مهمة

مهمة **لا تُعتبر منتهية** إلا إذا:
1. الكود مكتوب ويعمل محلياً.
2. اختبار Feature واحد على الأقل يغطي المسار السعيد + حالة فشل.
3. الصلاحيات مطبّقة (Policy).
4. النصوص في ملفات الترجمة (ع + EN).
5. الإعدادات المرتبطة مُضافة للوحة التحكم.
6. لا استعلامات N+1 (فحص بـ Debugbar/Pulse).
7. RTL وموبايل مُختبران بصرياً.
8. مراجعة كود من طرف ثانٍ (أو المراجعة الذاتية المزدوجة في 8.3).
9. CI أخضر بالكامل.
10. مذكورة في تقرير المرحلة.

## 8.5 هيكل تقرير المرحلة
كل مرحلة تُقفل بملف `docs/reports/phase-NN.md` يحتوي:
- ما تم إنجازه (مقابل نطاق المرحلة المخطط)
- ما لم يُنجز ولماذا، وإلى أي مرحلة انتقل
- نتائج المراجعتين (ماذا اكتُشف؟ ماذا أُصلح؟)
- مقاييس: عدد الاختبارات · التغطية · Lighthouse · عدد الاستعلامات في الصفحات الرئيسية
- الديون التقنية المسجّلة
- المخاطر المستجدة
- ما يحتاج قراراً من صاحب المشروع
