# 06 — الأداء والسيو (أولوية قصوى) + بلجن السيو الداخلي

> صاحب المشروع حدّد **سرعة الأداء والسيو** كأولوية أولى. لذلك هذه الوثيقة ليست "قائمة نصائح"،
> بل **عقد فني بأرقام قابلة للقياس** وبنود تنفيذية تدخل في تعريف "منتهي" لكل مرحلة.

## 🎯 القسم الأول: الأداء

### 6.1 ميزانية الأداء (Performance Budget) — أرقام مُلزِمة

| المؤشّر | الهدف | الحد الأحمر (يمنع الإطلاق) |
|---------|-------|---------------------------|
| **LCP** (موبايل 4G) | ≤ 2.0s | 2.5s |
| **INP** | ≤ 150ms | 200ms |
| **CLS** | ≤ 0.05 | 0.1 |
| **TTFB** (صفحة مؤرشفة) | ≤ 200ms | 500ms |
| **TTFB** (صفحة مسجّل دخول) | ≤ 400ms | 800ms |
| حجم JS الأولي (مضغوط) | ≤ 180KB | 250KB |
| حجم CSS الأولي | ≤ 60KB | 90KB |
| عدد استعلامات SQL / صفحة | ≤ 25 | 50 |
| زمن بدء تشغيل الفيديو | ≤ 1.5s | 3s |
| Lighthouse Performance (موبايل) | ≥ 90 | 80 |

> **بوابة CI:** أي Pull Request يتجاوز الحد الأحمر في Lighthouse CI **يُرفض آلياً**.

### 6.2 استراتيجية الأداء — 6 طبقات

#### الطبقة 1: الخادم (Runtime)
- **Laravel Octane + FrankenPHP** — يُبقي التطبيق في الذاكرة → توفير 30–60ms لكل طلب مقارنة بـ PHP‑FPM.
- PHP 8.4 + **OPcache + JIT** + preloading للكلاسات الساخنة.
- **قاعدة صارمة:** `Model::preventLazyLoading()` في كل البيئات → استحالة وجود N+1 في الإنتاج.
- استعلامات مُصمّمة: `select()` محدّد بدل `*`، فهارس مركّبة، `EXPLAIN` إلزامي لأي استعلام في مسار ساخن.
- **عدّادات مُجمّعة** (`students_count`, `reviews_count`, `rating_avg`, `lessons_count`) تُحدَّث بأحداث — لا `COUNT()` لحظي أبداً.
- عمليات ثقيلة (شهادات PDF، بريد، ترميز فيديو، تقارير، فهرسة) → **طوابير** حصراً.

#### الطبقة 2: قاعدة البيانات
- MySQL 8.4 مضبوط: `innodb_buffer_pool_size` = 60–70% من الذاكرة.
- فهارس مُخطّطة مسبقاً على: `(user_id, course_id)` · `(enrollment_id, lesson_id)` · `(course_id, position)` · `(status, published_at)` · `(slug)`.
- **نسخة قراءة (Read Replica)** جاهزة للتقارير عند النمو.
- تقسيم الجداول الضخمة (`activity_log`, `lesson_progress`) بالتاريخ عند تجاوز 10 مليون صف.
- أرشفة تلقائية للسجلات الأقدم من 12 شهراً.

#### الطبقة 3: الكاش (متعدد المستويات)
| المستوى | المحتوى | المدة | الإبطال |
|---------|---------|------|---------|
| **CDN / Edge** | HTML لصفحات الزوّار (رئيسية، كتالوج، مقال، صفحة كورس) | 5–60 دقيقة | Purge بالوسم عند النشر/التعديل |
| **Redis — Full Page** | نفس الصفحات لغير المسجّلين | 15 دقيقة | Cache Tags |
| **Redis — Fragment** | الرأس، التذييل، القوائم، البلوكات، الودجت | 24 ساعة | عند تعديل المصدر |
| **Redis — Query** | الإعدادات، الترجمات، التصنيفات، أسعار الصرف | ∞ | عند الكتابة |
| **Browser** | الأصول (JS/CSS/صور/خطوط) | سنة (hashed) | تغيير اسم الملف |
| **Octane Memory** | الحاويات والقيم الثابتة | حياة العملية | إعادة تشغيل |

- **صفحات المسجّلين لا تُكاش كاملة** — نستخدم Fragment Caching + تحميل الأجزاء الشخصية عبر طلب منفصل.

#### الطبقة 4: الواجهة
- **SSR** لكل صفحة تهم جوجل → HTML كامل في الاستجابة الأولى.
- **Code splitting** حسب المسار + `defer` لكل ما ليس حرجاً.
- **Critical CSS** مضمّن inline، والباقي غير حاجب.
- **الخطوط:** `font-display: swap` + `preload` + **مجموعة فرعية عربية (subset)** — الخط العربي الكامل قد يتجاوز 300KB؛ التقسيم يخفضه إلى ~40KB.
- **الصور:** AVIF/WebP + `srcset` + أبعاد صريحة (يمنع CLS) + `loading="lazy"` عدا صورة LCP + `fetchpriority="high"` لها.
- **الفيديو:** لا تحميل تلقائي للمشغّل؛ صورة مصغّرة أولاً ثم تحميل عند النقر.
- منع الخطوط والسكربتات الخارجية الحاجبة (استضافة ذاتية للخطوط).

#### الطبقة 5: البنية التحتية
- خادم في **أوروبا (فرانكفورت)** أو **البحرين/الإمارات** — الأقرب زمنياً للسوق المصري/الخليجي.
- **CDN** (Cloudflare / Bunny) أمام كل شيء، مع Cache Rules دقيقة.
- HTTP/3 + Brotli + TLS 1.3 + `early hints (103)`.
- فصل الطوابير والجدولة على عملية/خادم مستقل عن الويب.

#### الطبقة 6: القياس المستمر
- **RUM حقيقي** (بيانات مستخدمين فعليين) عبر `web-vitals` → جدول داخلي + Grafana.
- **Lighthouse CI** على كل PR لـ 6 صفحات نموذجية.
- **Laravel Pulse** — أبطأ المسارات، أبطأ الاستعلامات، أثقل الوظائف.
- تنبيه Slack عند تجاوز أي مؤشر عتبته لمدة 15 دقيقة.

## 🔍 القسم الثاني: بلجن السيو الداخلي

> بديل كامل عن Yoast/RankMath، **مبني داخلياً** ومصمّم لمنصة كورسات ثنائية اللغة.

### 6.3 وحدات بلجن السيو

#### أ. السيو لكل صفحة (On‑Page)
لكل كيان (كورس · منتج · خدمة · مقال · صفحة · تصنيف · مدرّس) وبكل لغة:
- `title` مع **قوالب متغيّرات**: `{title} | {category} | {site}`
- `meta description` (مع عدّاد وتحذير عند تجاوز الطول المثالي)
- `canonical` (تلقائي + تجاوز يدوي)
- `robots`: index/noindex · follow/nofollow · noarchive · max-snippet · max-image-preview
- **Open Graph** + **Twitter Card** + صورة مشاركة (توليد تلقائي إن لم تُرفع)
- الكلمة المفتاحية المستهدفة + **تحليل فوري** (تواجدها في العنوان/الوصف/H1/أول فقرة/الرابط/نص بديل للصور)
- **معاينة حيّة** لشكل النتيجة في جوجل (بالعربية والإنجليزية)
- **مؤشّر جاهزية** أخضر/أصفر/أحمر لكل صفحة + قائمة "صفحات تحتاج تحسين"

#### ب. البيانات المنظّمة (Schema.org — JSON‑LD)
تُولَّد **آلياً** لكل نوع:
| النوع | الاستخدام |
|-------|-----------|
| `Organization` + `WebSite` + `SearchAction` | الموقع كله |
| **`Course` + `CourseInstance`** | صفحة الكورس (سعر، مدة، لغة، مدرّس، طريقة التقديم) |
| `Product` + `Offer` + `AggregateRating` + `Review` | المنتجات والكورسات المدفوعة |
| `Service` + `Offer` | الخدمات |
| `Article` / `BlogPosting` | المقالات |
| `VideoObject` | كل درس فيديو عام (مهم جداً لظهور الفيديو في النتائج) |
| `BreadcrumbList` | كل الصفحات |
| `Person` | صفحة المدرّس |
| `ItemList` | صفحات الكتالوج |
| `EducationalOrganization` | الهوية التعليمية |

> ملاحظة: **نتائج FAQ الغنية أُوقفت في جوجل (مايو 2026)** — نُبقي `FAQPage` لفائدة الفهم الدلالي
> ومحرّكات الذكاء الاصطناعي، لكن لا نعتمد عليها في توقّع الظهور الغني.

#### ج. تعدّد اللغات
- `hreflang` تلقائي لكل صفحة + `x-default` + التحقق من التماثل (كل نسخة تشير للأخرى).
- `<html lang="ar" dir="rtl">` صحيح لكل لغة.
- **Slug عربي مقروء** (`/دورة-لارفيل`) أو **مُعرَّب لاتينياً** (`/dawrat-laravel`) — قرار قابل للضبط لكل نوع محتوى.
- خرائط موقع منفصلة لكل لغة داخل فهرس واحد.

#### د. الفهرسة والزحف
- **خرائط موقع ديناميكية**: `/sitemap.xml` (فهرس) → `sitemap-courses.xml` · `sitemap-posts.xml` · `sitemap-pages.xml` · `sitemap-instructors.xml` · `sitemap-categories.xml` · `sitemap-images.xml` · `sitemap-video.xml`
- تحديث تلقائي عند النشر + `lastmod` صحيح + تقسيم كل 5000 رابط.
- **`robots.txt` قابل للتحرير** من اللوحة مع تحذير عند حجب شيء مهم.
- **إدارة إعادة التوجيه (301/302/410)** — واجهة كاملة + استيراد CSV + **كشف تلقائي عند تغيير أي slug** (يقترح إنشاء 301) + سجل استخدام كل قاعدة.
- **رصد 404**: تسجيل كل رابط مفقود مع عدد المرات والمصدر، وزر "أنشئ إعادة توجيه" مباشرة.
- ربط **Google Search Console API** → عرض الانطباعات والنقرات ومتوسط الترتيب **داخل لوحة التحكم لكل صفحة**.
- **IndexNow** + طلب فهرسة فوري عند نشر محتوى جديد.

#### هـ. السيو الداخلي والمحتوى
- **اقتراح روابط داخلية** آلي (يقترح ربط مقال بكورس ذي صلة).
- كشف **الروابط المكسورة** دورياً.
- كشف **المحتوى المكرّر** (عناوين/أوصاف متطابقة).
- تحليل قابلية القراءة للعربية (طول الجملة، الفقرة، العناوين الفرعية).
- **صفحات ركيزة (Pillar/Cluster)** لتنظيم بنية الموضوعات.
- إدارة **الوسوم البديلة للصور** بشكل جماعي.

#### و. سيو محرّكات الذكاء الاصطناعي (AEO/GEO) — مهم في 2026
- `llms.txt` يصف الموقع للنماذج اللغوية.
- بيانات منظّمة غنية (هي المصدر الأول الذي تعتمد عليه نتائج الذكاء الاصطناعي).
- إجابات مباشرة ومختصرة أعلى كل صفحة محتوى.
- التحكم في وصول زواحف الذكاء الاصطناعي (السماح/المنع لكل زاحف).

#### ز. المراقبة والتقارير
لوحة سيو داخل الإدارة تعرض: الصفحات الأعلى أداءً · الكلمات الصاعدة/الهابطة ·
أخطاء الفهرسة · صفحات بلا وصف · صفحات بطيئة · **Core Web Vitals من بيانات حقيقية** ·
تقرير أسبوعي بالبريد.

### 6.4 إعدادات بلجن السيو (شاشة الإعدادات)
```
عام:         تفعيل · قوالب العناوين لكل نوع · الفاصل · الوصف الافتراضي ·
             صورة المشاركة الافتراضية · اسم الموقع في النتائج
الفهرسة:     noindex لصفحات البحث/الترقيم/الوسوم/الأرشيف · robots.txt
البيانات:    تفعيل كل نوع Schema على حدة · بيانات المؤسسة · الشعار · التواصل
الخرائط:     تفعيل · ما يُدرج · عدد الروابط لكل ملف · الأولويات
اللغات:      hreflang · نمط الروابط · معالجة العربية في الـ slug
التحقق:      Google · Bing · Yandex · Pinterest · Facebook Domain
التكامل:     Search Console API · IndexNow · Analytics
التوجيه:     قواعد 301 · الكشف التلقائي · سلوك 404
الذكاء:      llms.txt · التحكم بزواحف الذكاء الاصطناعي
متقدم:       كود مخصّص في <head> · قبل </body> · لكل لغة على حدة
```

### 6.5 قواعد سيو مضمّنة في المعمارية (ليست خياراً)
1. **SSR افتراضياً** لكل صفحة عامة — لا اعتماد على JS للمحتوى الأساسي.
2. **رابط واحد فقط لكل محتوى** (بلا `?ref=`، بلا نسخ متعددة) + canonical صارم.
3. **بنية روابط ثابتة منذ اليوم الأول** — تغيير الروابط لاحقاً أغلى خطأ في السيو.
4. **H1 واحد** لكل صفحة، وتسلسل عناوين صحيح.
5. **فتات الخبز (Breadcrumbs)** مرئية + منظّمة في كل صفحة داخلية.
6. **الترقيم (Pagination)** بروابط حقيقية `<a href>` — لا "تحميل المزيد" فقط.
7. **صفحة لكل شيء له قيمة بحثية**: كورس · تصنيف · مدرّس · مستوى · لغة · سعر (مجاني) · مقال.
8. **معاينة مجانية مفتوحة للزوّار** لدرس أو اثنين — محتوى مؤرشف = زيارات.
9. **التقييمات في HTML** لا عبر JS — مصدر النجوم في النتائج.
10. **صفحات هبوط مُولَّدة** لكل تصنيف × مدينة × مستوى عند الحاجة (بحذر من المحتوى الضعيف).
