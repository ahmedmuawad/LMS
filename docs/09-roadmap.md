# 09 — خارطة الطريق والمراحل والتقديرات

كل مرحلة تُنفَّذ بدورة [المنهجية](08-methodology.md): توثيق ← تخطيط ← تنفيذ ← مراجعة ← مراجعة بعينين ← سد الثغرات ← إقفال.

## 9.1 نظرة عامة على المراحل

| # | المرحلة | المدة | المخرج الرئيسي |
|---|---------|------|----------------|
| **0** | التوثيق والتخطيط والتدقيق | 1–2 أسبوع | هذه الوثائق + تدقيق قاعدة WordPress الفعلية |
| **1** | الأساس (Foundation) | 3 أسابيع | مشروع يعمل: مصادقة، أدوار، لغات، إعدادات، وسائط، لوحة إدارة، سيو أساسي، CI/CD |
| **2** | نواة الـ LMS | 5 أسابيع | كورسات كاملة + دروس + فيديو محمي + اختبارات + واجبات + تقدّم + شهادات |
| **3** | التجارة والمدفوعات | 4 أسابيع | منتجات + سلة + دفع محلي ودولي + طلبات + فواتير + كوبونات + اشتراكات |
| **4** | الخدمات والمحتوى والـ Page Builder | 4 أسابيع | خدمات وحجوزات + مدونة + محرر صفحات + نماذج + منتجات مادية |
| **5** | النمو والمجتمع | 3 أسابيع | إشعارات (بريد/واتساب/Push) + تسويق بالعمولة + سلة متروكة + تقييمات + نقاشات + PWA |
| **6** | الترحيل والسيو والإطلاق | 3 أسابيع | ترحيل كامل + خريطة 301 + تدقيق أداء وسيو + اختبار قبول + إطلاق |
| **7** | الاستقرار وما بعد الإطلاق | 2 أسبوع | مراقبة، إصلاحات، تحسينات مبنية على بيانات حقيقية |
| | **الإجمالي** | **25–29 أسبوعاً** | (≈ 6–7 أشهر) |

**مسار MVP المختصر (إن أردنا إطلاقاً أسرع):** المراحل 0→1→2→3→6 = **16–18 أسبوعاً**،
ثم المراحل 4 و5 بعد الإطلاق. **هذا هو المسار الموصى به** — إيراد أبكر ومخاطرة أقل.

## 9.2 تفصيل كل مرحلة

### المرحلة 0 — التوثيق والتخطيط (1–2 أسبوع)
- ✅ تحليل WPLMS · التقنيات · المعمارية · نموذج البيانات · خطة الترحيل · السيو والأداء · المنافسون · المنهجية
- ⬜ **تدقيق قاعدة بيانات WordPress الفعلية** (أهم بند): الأحجام، الإضافات، بنية `vibe_course_curriculum` الحقيقية، جداول غير معروفة
- ⬜ جرد الروابط من Search Console
- ⬜ تحديد الهوية البصرية ونظام التصميم (Design System) + نماذج Figma للشاشات الأساسية
- ⬜ إقرار القرارات المفتوحة ([وثيقة 10](10-open-questions.md))

**بوابة الإقفال:** خطة مُقرّة من صاحب المشروع + تقرير تدقيق قاعدة البيانات + تقديرات مثبّتة.

### المرحلة 1 — الأساس (3 أسابيع)
- إعداد Laravel 13 + Docker + Octane + CI/CD + بيئتا Staging/Production
- بنية الموديولات + سجل الموديولات + **طبقة الإعدادات** + صفحات إعدادات مُولَّدة
- **نظام اللغات** (ع/EN) + التوجيه + محرّر الترجمات + RTL
- المصادقة: تسجيل، دخول، تحقق بريد/OTP، استعادة، 2FA، Passkeys، تسجيل اجتماعي
- الأدوار والصلاحيات (5 أدوار) + سجل التدقيق
- مكتبة الوسائط (رفع، مجلدات، تحويلات، WebP/AVIF، S3)
- لوحة الإدارة (Filament) + هيكل التنقّل + لوحة مؤشرات فارغة
- **نظام التصميم** في الواجهة (Tailwind + مكوّنات أساسية + وضع داكن + RTL)
- **بلجن السيو — الجزء الأساسي**: عناوين، أوصاف، canonical، robots، خرائط موقع، hreflang، إعادة توجيه، 404
- الأداء: كاش، Pulse، Lighthouse CI، ميزانية الأداء في CI

**بوابة الإقفال:** موقع فارغ لكنه سريع، ثنائي اللغة، آمن، مع لوحة إدارة تعمل، وCI أخضر.

### المرحلة 2 — نواة الـ LMS (5 أسابيع)
- الكورسات: إنشاء، تصنيفات، مستويات، مدرّسون، حالات نشر، معاينة
- المنهج: أقسام + عناصر (سحب وإفلات) + فتح تدريجي + تسلسل إجباري
- الدروس: فيديو (Bunny) · صوت · نص · PDF · مرفقات · مسودة نصية
- **مشغّل الكورس**: استئناف، تتبّع مشاهدة، ملاحظات، تنقّل، سرعة، ترجمات
- الاختبارات: 8–10 أنواع أسئلة، بنك أسئلة، ثابت/ديناميكي، مؤقّت، محاولات، تصحيح آلي ويدوي
- الواجبات: رفع، تصحيح، ملاحظات، إعادة تسليم
- التقدّم والإكمال + الشارات
- **الشهادات**: مُنشئ قوالب، إصدار، PDF، كود تحقق، صفحة تحقق عامة، QR
- لوحة الطالب + لوحة المدرّس (إحصاءات، طلاب، تصحيح)
- صفحة الكورس العامة (سيو كامل + Schema `Course` + `VideoObject`)

**بوابة الإقفال:** طالب يستطيع التسجيل يدوياً في كورس، إنهاؤه، اجتياز اختبار، والحصول على شهادة.

### المرحلة 3 — التجارة والمدفوعات (4 أسابيع)
- المنتجات كمظلة موحّدة + ربط بالكورسات
- السلة + الدفع (Checkout) + شراء بنقرة للكورسات + الشراء كضيف
- **البوابات:** Paymob · Fawry · Stripe · PayPal · تحويل بنكي بإيصال · محفظة داخلية
- الطلبات + الحالات + الاسترداد + الفواتير PDF + الإيصالات
- الكوبونات والعروض والحزم
- الاشتراكات والعضويات + محرك التجديد + فترة السماح + إعادة المحاولة
- التسجيل التلقائي في الكورس بعد الدفع + العمولات للمدرّسين
- تقارير مبيعات أساسية

**بوابة الإقفال:** عملية شراء حقيقية بجنيه مصري عبر Paymob وFawry تنتهي بتسجيل تلقائي وفاتورة.

### المرحلة 4 — الخدمات والمحتوى والـ Page Builder (4 أسابيع)
- الخدمات: باقات ثلاثية، إضافات، نموذج متطلبات، مدة تسليم، تعديلات، Escrow، نزاعات
- الحجوزات: تقويم توافر، حجز، تذكيرات، رابط اجتماع
- المدونة: مقالات، تصنيفات، وسوم، تعليقات، ذات صلة، سيو كامل
- **Page Builder**: ~25 بلوك + قوالب جاهزة + معاينة + جدولة + ترجمة لكل بلوك
- النماذج المخصّصة + المنتجات المادية (مخزون، شحن) + القوائم والبانرات

**بوابة الإقفال:** المدير يبني صفحة هبوط كاملة بنفسه بلا مبرمج، وعميل يشتري خدمة ويستلمها.

### المرحلة 5 — النمو والمجتمع (3 أسابيع)
- الإشعارات: بريد + **واتساب** + SMS + Web Push + داخل الموقع + مصفوفة التفضيلات
- قوالب البريد القابلة للتحرير (~40 حدثاً، ع/EN)
- السلة المتروكة + تسلسلات تسويقية + تذكيرات الخمول والإكمال
- التقييمات والمراجعات + الاعتدال
- النقاشات + اسأل المدرّس + الرسائل
- التسويق بالعمولة (Affiliates) + تتبّع + تحويلات
- PWA + تثبيت + مشاهدة دون اتصال
- التحليلات (GA4 + Meta CAPI + تتبّع تجارة محسّن)
- التقارير المتقدمة (تعليمية + مالية + تسويقية)

**بوابة الإقفال:** كل حدث مهم يصل للمستخدم على القناة الصحيحة، والتقارير تعكس الواقع.

### المرحلة 6 — الترحيل والسيو والإطلاق (3 أسابيع)
- سكربتات الترحيل الكاملة + التشغيل التجريبي (مرتين على الأقل)
- تقرير التحقق + إصلاح الفروق
- خريطة إعادة التوجيه الكاملة + اختبارها آلياً
- تدقيق سيو شامل (Screaming Frog) + تدقيق أداء + تدقيق أمني
- اختبار قبول المستخدم (UAT) مع صاحب المشروع وفريق الدعم
- اختبار حِمل (Load test) على ذروة متوقعة
- تدريب فريق الإدارة + دليل استخدام بالعربية
- **الإطلاق** حسب خطة Cutover

**بوابة الإقفال:** الموقع الجديد يعمل بالبيانات الحقيقية، والروابط القديمة تعمل، والمؤشرات ضمن الميزانية.

### المرحلة 7 — الاستقرار (2 أسبوع)
مراقبة 24/7 · إصلاح ما يظهر · متابعة Search Console يومياً · تحسينات على بيانات حقيقية · تسليم نهائي.

## 9.3 الفريق المقترح

| الدور | العدد | المشاركة |
|-------|------|---------|
| قائد تقني / معماري | 1 | كامل |
| مطوّر Laravel أول | 1 | كامل |
| مطوّر Laravel | 1–2 | كامل |
| مطوّر واجهات (Vue/Tailwind) | 1 | كامل |

## 9.4 التكاليف التشغيلية الشهرية (تقديرية)

| البند | صغير (<5k مستخدم) | متوسط (5–50k) |
|-------|-------------------|---------------|
| خوادم (تطبيق + قاعدة + Redis) | $80–150 | $300–600 |
| تخزين + CDN | $20–40 | $80–200 |
| **فيديو (Bunny Stream)** | $30–100 | $200–800 |
| بريد (SES/Postmark) | $10–30 | $50–150 |
| Meilisearch | مع الخادم | $50–100 |
| مراقبة (Sentry/Grafana) | $0–30 | $50–100 |
| نسخ احتياطي | $10 | $30 |
| واتساب API | $20–50 | $100–300 |
| **الإجمالي** | **≈ $170–410** | **≈ $860–2280** |
| رسوم بوابات الدفع | 2–3% من المبيعات | 2–3% |

> الفيديو والنطاق الترددي هما البند المتحرّك الأكبر — يجب مراقبتهما أسبوعياً بعد الإطلاق.

## 9.5 سجل المخاطر

| الخطر | الاحتمال | الأثر | التخفيف |
|-------|---------|------|---------|
| بيانات WPLMS أعقد من المتوقع | عالٍ | عالٍ | تدقيق فعلي في المرحلة 0 قبل تثبيت التقديرات |
| **فقدان ترتيب جوجل** | متوسط | **حرج** | خريطة 301 + الحفاظ على الروابط + مراقبة 60 يوماً |
| تضخّم نطاق الـ Page Builder | **عالٍ** | عالٍ | مكتبة بلوكات مغلقة (25 بلوك) — أي إضافة تحتاج قراراً |
| تأخّر اعتماد بوابات الدفع | متوسط | عالٍ | بدء إجراءات Paymob/Fawry في **المرحلة 0** لا 3 |
| تكلفة الفيديو تتجاوز المتوقع | متوسط | متوسط | مراقبة + حدود جودة + كاش على CDN |
| تغيّر المتطلبات أثناء التنفيذ | عالٍ | متوسط | إقفال نطاق كل مرحلة كتابياً + سجل تغييرات |
| اعتماد على شخص واحد | متوسط | عالٍ | توثيق + مراجعة كود متبادلة |
| مشاكل أداء تظهر بعد الإطلاق | متوسط | عالٍ | ميزانية أداء في CI من المرحلة 1 + اختبار حِمل قبل الإطلاق |
| رفض المستخدمين للواجهة الجديدة | متوسط | متوسط | إشراك عيّنة مستخدمين في UAT + فترة تعايش |

## 9.6 مؤشرات نجاح المشروع (بعد 90 يوماً من الإطلاق)

| المؤشّر | الهدف |
|---------|-------|
| زيارات جوجل العضوية | ≥ 100% من مستوى ما قبل الترحيل (ثم نمو) |
| متوسط LCP (بيانات حقيقية) | ≤ 2.0s |
| معدل تحويل الزائر إلى مشترٍ | +20% مقارنة بالقديم |
| معدل إتمام الشراء (Checkout) | +25% (بفضل الدفع المحلي) |
| معدل إكمال الكورسات | +15% (بفضل التذكيرات) |
| تذاكر الدعم المتعلقة بمشاكل تقنية | −50% |
| زمن نشر ميزة جديدة | من أسابيع إلى أيام |
