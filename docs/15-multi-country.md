# 15 — التوسّع الدولي: الدول والعملات والضرائب

> النظام يُباع في أكثر من دولة وبأكثر من عملة — **على المستويين**:
> نحن نبيع اشتراكات لمشتركين في دول مختلفة، وكل مشترك يبيع لطلابه بعملته وضرائبه.
> هذا ليس إعداداً يُضاف لاحقاً؛ هو قرار معماري يدخل في تصميم كل جدول مالي من اليوم الأول.

---

## 15.1 القاعدة الحاكمة: ٤ عملات مختلفة في المعاملة الواحدة

```
عملة العرض        ما يراه المستخدم على الشاشة        EGP
عملة التسعير      ما ثُبّت عليه السعر في الخطة       USD
عملة التحصيل      ما تقبله البوابة فعلياً            EGP
عملة التسوية      ما يصل حساب المستفيد               USD
```

**كل جدول مالي يخزّن:** `amount` + `currency` + `fx_rate` + `base_amount` (بعملة الأساس) + `captured_at`.
> **لماذا؟** لأن سعر الصرف يتغيّر. تقرير إيرادات يعيد الحساب بسعر اليوم = تقرير كاذب.
> نخزّن السعر لحظة المعاملة ونجمّده إلى الأبد.

## 15.2 نموذج الدول

```
countries
  code (ISO 3166-1)      name(json ar/en)      dial_code
  currency               locale_default         timezone_default
  tax_enabled            tax_rate               tax_name(json)     tax_id_label
  tax_inclusive_display  (شامل/غير شامل في العرض)
  gateways(json)         ← البوابات المتاحة في هذه الدولة مرتّبة
  e_invoice_provider     ← ETA · ZATCA · none
  phone_pattern          address_format         week_start
  numerals(arabic|hindi) calendar(gregorian|hijri|both)
  consumer_refund_days   is_active
```

### الدول في الإطلاق الأول

| الدولة | العملة | الضريبة (افتراضي — تُراجع قانونياً) | البوابات | فاتورة إلكترونية |

| 🇪🇬 مصر | EGP | ~14% VAT | Paymob · Fawry · محافظ · تحويل · **أكواد شحن** | **ETA** (منظومة الفاتورة الإلكترونية) |
| 🇸🇦 السعودية | SAR | ~15% VAT | Moyasar · Tap · HyperPay · Mada · تابي/تمارا | **ZATCA / فاتورة** |
| 🇦🇪 الإمارات | AED | ~5% VAT | Tap · Stripe · Network Intl | قيد التطبيق تدريجياً |
| 🇰🇼 الكويت | KWD | حالياً بلا VAT | KNET عبر Tap | — |
| 🇶🇦 قطر | QAR | حالياً بلا VAT | Tap · Stripe | — |
| 🇯🇴 الأردن | JOD | ~16% GST | Stripe · HyperPay | — |

> ⚠️ **إلزامي:** النسب والقواعد أعلاه **قيم افتراضية قابلة للتعديل من لوحة الإدارة**،
> ويجب مراجعتها مع محاسب/مستشار ضريبي في كل دولة قبل التفعيل. النظام لا يفترض ثباتها في الكود.

## 15.3 العملات

```
currencies
  code (ISO 4217)   symbol(json)   name(json)   decimals(0|2|3)
  position(before|after)  thousands_sep  decimal_sep
  rate_to_base      rate_updated_at   rate_source(manual|api)
  rounding_rule     is_active
```

### تفاصيل حرجة كثيراً ما تُنسى
| البند | القاعدة |
|-------|---------|
| **الخانات العشرية تختلف** | KWD/BHD/OMD = **3 خانات** · JPY = **0** · الباقي = 2 |
| **التخزين** | كل المبالغ **أعداد صحيحة بأصغر وحدة** (قروش/هللات/فلوس) — **ممنوع `float` نهائياً** |
| **التقريب** | يُطبَّق مرة واحدة عند العرض/الفوترة، لا في كل عملية حسابية |
| **التقريب النفسي** | قابل للضبط لكل عملة: `.99` أو `.00` أو `9` — مصر تفضّل 199 لا 200 |
| **أسعار الصرف** | تحديث يومي من مصدر موثوق + **تجميد السعر داخل السلة 30 دقيقة** حتى لا يتغيّر أثناء الدفع |
| **العرض** | `1,250.00 ج.م` مقابل `SAR 1,250.00` — الموضع والفاصل يختلفان لغةً ودولةً |

### استراتيجية التسعير — قرار مهم
| الطريقة | الوصف | متى |
|---------|-------|-----|
| **تسعير ثابت لكل عملة** ✅ موصى به | تحدّد يدوياً: 199 EGP · 29 SAR · 9 USD | يحترم القوة الشرائية ويعطي أسعاراً "جميلة" |
| تحويل آلي | سعر أساسي × سعر الصرف | يعطي أرقاماً قبيحة ويتقلّب — للعملات النادرة فقط |

**النظام يدعم الاثنين:** حقل `prices(json)` لكل خطة/منتج، مع احتياط التحويل الآلي عند غياب سعر مثبّت.

## 15.4 الضرائب

### المستوى 1 — نحن نفوتر المشترك
```
□ تحديد الدولة من: بلد التسجيل + عنوان الفوترة + IP (للكشف فقط)
□ B2C → تُضاف الضريبة بنسبة دولة المشترك
□ B2B مع رقم ضريبي صحيح → قد ينطبق "التحصيل العكسي" (Reverse Charge) حسب الدولة
□ تخزين: tax_country · tax_rate · tax_amount · tax_id · tax_evidence(json)
□ التحقق من صيغة الرقم الضريبي لكل دولة (وربط API للتحقق حيث يتاح)
□ تقارير ضريبية شهرية لكل دولة — جاهزة للإقرار
```

### المستوى 2 — المشترك يفوتر طلابه
```
□ لكل مشترك: تفعيل الضريبة · النسبة · الاسم · الرقم الضريبي · شامل/غير شامل
□ فئات ضريبية لكل منتج (كورس تعليمي قد يُعفى في بعض الدول)
□ نسب مختلفة لدول الطلاب إن باع دولياً
□ الفاتورة تحمل بيانات المشترك القانونية لا بياناتنا
```

### العرض شامل أم غير شامل
سلوكيات السوق تختلف: مصر تعرض **شاملاً**، وبعض أسواق B2B تعرض **غير شامل + الضريبة سطراً منفصلاً**.
→ إعداد لكل دولة ولكل مشترك، **والسعر المعروض يتغيّر تلقائياً حسب دولة الزائر**.

## 15.5 الفوترة الإلكترونية (متطلب قانوني لا خيار)

| الدولة | المنظومة | ما يتطلبه تقنياً |
|--------|---------|-------------------|
| 🇪🇬 مصر | **ETA — منظومة الفاتورة الإلكترونية** | توقيع رقمي · إرسال للمنظومة · استلام UUID · كود موحّد للسلعة/الخدمة (GS1/EGS) |
| 🇸🇦 السعودية | **ZATCA — فاتورة (المرحلة الثانية)** | فاتورة XML (UBL 2.1) · **QR إلزامي** · ختم تشفيري · ربط API مع الهيئة |
| 🇦🇪 الإمارات | قيد التطبيق التدريجي | تصميم مرن لاستيعابها |

**التصميم:** واجهة موحّدة `EInvoiceProvider` + مشغّل لكل دولة، يعمل **بشكل غير متزامن (طوابير)** مع إعادة محاولة وسجل كامل وحالة لكل فاتورة (`pending · submitted · accepted · rejected`).
الرفض يُعرض للمشترك بسبب مفهوم وزر إعادة إرسال.

> **ملاحظة صريحة:** ربط ETA وZATCA يحتاج تسجيلاً وشهادات وبيئة اختبار رسمية،
> ويستغرق **3–6 أسابيع إدارياً**. يجب بدء الإجراءات مبكراً كما في بوابات الدفع.

## 15.6 التحويلات للمدرّسين (Payouts)

```
□ عملة التحويل قد تختلف عن عملة البيع
□ طرق: تحويل بنكي محلي · محفظة · InstaPay · PayPal · Wise · نقدي في السنتر
□ الحد الأدنى للتحويل لكل عملة
□ دورة التحويل: أسبوعية/شهرية/عند الطلب
□ خصم ضريبي عند المنبع (Withholding) حيث ينطبق — نسبة قابلة للضبط لكل دولة
□ فترة تجميد قبل التحويل (تغطية الاستردادات) — قابلة للضبط
□ كشف حساب PDF لكل مدرّس بعملته
```

## 15.7 الأقلمة (Localization) — أبعد من الترجمة

| البند | التفصيل |
|-------|---------|
| **اللغات** | عربي · إنجليزي في الإطلاق · البنية تقبل الفرنسية (المغرب/الجزائر) والتركية لاحقاً بلا إعادة بناء |
| **الأرقام** | عربية `123` أو هندية `١٢٣` — إعداد لكل مشترك (مصر تفضّل العربية، الخليج يتفاوت) |
| **التقويم** | ميلادي · **هجري** · الاثنان معاً — مهم جداً للسوق السعودي |
| **بداية الأسبوع** | السبت (الخليج ومصر) · الأحد · الاثنين — يؤثر على **جداول حصص السنتر** |
| **المنطقة الزمنية** | لكل مشترك، وكل التواريخ تُخزَّن UTC وتُعرض بتوقيته |
| **الهواتف** | تحقق حسب الدولة + مفتاح دولي + توحيد الصيغة قبل التخزين |
| **العناوين** | تنسيق مختلف لكل دولة (المحافظة/المنطقة/الرمز البريدي) |
| **العطلات** | تقويم عطلات رسمي لكل دولة يؤثر على جدولة الحصص والتذكيرات |
| **أوقات الصلاة** | خيار لتجنّب جدولة الحصص وقت الصلاة (ميزة محلية يقدّرها السوق) |
| **الاتجاه** | RTL/LTR تلقائي حسب اللغة |

## 15.8 الامتثال وحماية البيانات

| الإطار | الأثر على التصميم |
|--------|-------------------|
| **GDPR** (أوروبا) | موافقات · تصدير بياناتي · حق الحذف · سجل معالجة |
| **PDPL السعودي** | قد يتطلب **إقامة البيانات داخل المملكة** لبعض الفئات ← معماريتنا (قاعدة لكل مشترك) تسمح بوضع قاعدة مشترك في shard إقليمي |
| **قانون حماية البيانات المصري** | موافقات وإخطارات |
| **قوانين حماية المستهلك** | مدة الاسترداد تختلف بالدولة ← `consumer_refund_days` لكل دولة |
| **بيانات القُصّر** | موافقة ولي الأمر إلزامية في نمط السنتر ← مبنية في بوابة أولياء الأمور |

**إقامة البيانات (Data Residency)** ميزة باقة: `dedicated_db` + `data_residency` تسمح بوضع مشترك في منطقة جغرافية محددة.

## 15.9 التسعير حسب الدولة (Regional Pricing)

نفس الباقة بأسعار مختلفة حسب القوة الشرائية:

| الباقة | 🇪🇬 مصر | 🇸🇦 السعودية | 🇦🇪 الإمارات | 🌍 دولي |
|--------|--------|-------------|-------------|---------|
| البداية | 499 EGP | 79 SAR | 79 AED | 19 USD |
| النمو | 1,499 EGP | 249 SAR | 249 AED | 59 USD |
| الاحترافية | 2,999 EGP | 499 SAR | 499 AED | 119 USD |
| السنتر | 1,999 EGP | 349 SAR | 349 AED | 89 USD |

> أرقام **توضيحية** — تُحدَّد بعد دراسة السوق. المهم أن **البنية تدعمها**:
> `plans.prices` = JSON لكل عملة، والدولة تُكتشف تلقائياً مع إمكانية التبديل يدوياً.

**حماية من الاستغلال:** كشف تعارض بين دولة الفوترة ودولة البطاقة وIP، مع مراجعة يدوية عند الشك.

## 15.10 ما يجب بناؤه في المرحلة 1 (وإلا استحال لاحقاً)

```
✅ كل المبالغ أعداد صحيحة بأصغر وحدة — لا float
✅ كل جدول مالي يحمل: currency + fx_rate + base_amount
✅ جدول countries و currencies من اليوم الأول
✅ طبقة Money موحّدة (جمع/طرح/تقريب/عرض) لا حساب يدوي في أي مكان
✅ اكتشاف الدولة والعملة واللغة في Middleware
✅ التواريخ UTC في التخزين دائماً
✅ الهواتف موحّدة الصيغة قبل التخزين
✅ واجهة TaxCalculator و EInvoiceProvider حتى لو بمشغّل فارغ
```
> إضافة تعدّد العملات لاحقاً على نظام بُني بعملة واحدة = **إعادة كتابة الطبقة المالية بالكامل**.
