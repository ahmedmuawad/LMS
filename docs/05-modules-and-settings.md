# 05 — نظام الموديولات (البلجنز الداخلية) وكتالوج الإعدادات الكامل

> المطلوب: **كل ميزة تُبنى كـ "بلجن" داخلي قابل للتفعيل/التعطيل، وله صفحة إعدادات كاملة**،
> بالضبط كتجربة WordPress — لكن بدون فوضاها الأمنية والأدائية.

## 5.1 معمارية نظام البلجنز الداخلي

### الفكرة
كل موديول = حزمة مستقلة داخل نفس الكود، تُسجّل نفسها في **سجل الموديولات (Module Registry)**:

```php
// app/Modules/Seo/SeoModule.php
class SeoModule extends Module
{
    public string $key     = 'seo';
    public string $name    = 'محرك السيو';
    public string $icon    = 'heroicon-o-magnifying-glass';
    public string $version = '1.0.0';
    public array  $requires = [];              // تبعيات على موديولات أخرى
    public bool   $canDisable = true;

    public function settingsSchema(): array    // ← يبني صفحة الإعدادات تلقائياً
    {
        return [
            Section::make('عام')->fields([
                Toggle::make('enabled')->default(true),
                Text::make('title_template')->default('{page} | {site}')->translatable(),
                Textarea::make('default_description')->translatable(),
                Media::make('default_og_image'),
            ]),
            Section::make('الفهرسة')->fields([
                Toggle::make('noindex_search_pages')->default(true),
                Toggle::make('noindex_paginated')->default(false),
                Code::make('robots_txt')->language('text'),
            ]),
            // ...
        ];
    }

    public function boot(): void { /* تسجيل routes / views / listeners */ }
}
```

### ما يحصل عليه كل موديول مجاناً
| الميزة | الوصف |
|--------|-------|
| **تفعيل/تعطيل** | من `/admin/modules` بضغطة واحدة، مع فحص التبعيات |
| **صفحة إعدادات مُولَّدة** | من `settingsSchema()` مباشرة — لا كتابة واجهة |
| **إعدادات مترجمة** | أي حقل عليه `->translatable()` يظهر بتبويبين (ع/EN) |
| **صلاحيات** | `module.seo.view` / `.manage` تلقائياً |
| **ترجمات** | `lang/{locale}/modules/seo.php` |
| **مهاجرات** | `Modules/Seo/database/migrations` |
| **سجل تدقيق** | كل تغيير إعداد يُسجَّل: من، متى، القيمة القديمة والجديدة |
| **تصدير/استيراد** | تصدير كل الإعدادات كـ JSON لنقلها بين البيئات |
| **Health Check** | فحص ذاتي: مفاتيح ناقصة؟ خدمة غير متصلة؟ |

### طبقة الإعدادات
```php
setting('seo.title_template');              // مع كاش وتحويل نوع تلقائي
setting('payments.paymob.enabled', false);
setting('lms.certificate.auto_issue');
setting()->translated('seo.default_description');  // حسب اللغة الحالية
```
- التخزين: جدول `settings` (group · key · value JSON · is_translatable · is_encrypted)
- **كاش كامل في Redis** يُبطَل عند أي تحديث → صفر استعلامات إعدادات في الطلب العادي
- المفاتيح الحساسة (API keys) **مشفّرة على مستوى العمود**
- ملف `config/` يبقى للثوابت التقنية فقط؛ كل ما يخصّ الأعمال في `settings`

## 5.3 كتالوج الإعدادات — كل خيار في الموقع

### ⚙️ 1) إعدادات عامة (General)

## 5.4 مبادئ تصميم الإعدادات (لتفادي فوضى WordPress)

1. **كل إعداد له قيمة افتراضية عاقلة** — الموقع يعمل بدون لمس أي إعداد.
2. **بحث فوري** في كل الإعدادات (`Ctrl+K`) — لا يضيع المدير بين 15 تبويباً.
3. **تحقق فوري (Validation)** — لا يمكن حفظ مفتاح API خاطئ؛ زر "اختبر الاتصال" في كل تكامل.
4. **شرح لكل خيار** بالعربية بلغة غير تقنية + مثال.
5. **إعدادات متقدّمة مطوية** خلف "إظهار الخيارات المتقدّمة".
6. **سجل تغييرات** لكل إعداد مع إمكانية الاسترجاع.
7. **بيئات منفصلة** — تصدير إعدادات Staging واستيرادها للإنتاج.
8. **صلاحيات دقيقة** — مدير التسويق يرى السيو والتحليلات فقط؛ المفاتيح المالية للمالك فقط.
