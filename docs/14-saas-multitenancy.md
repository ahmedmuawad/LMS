# 14 — معمارية الـ SaaS متعدد المستأجرين

> المنتج ليس موقعاً واحداً. هو **منصة تُباع بالاشتراك** لمدرّسين وأكاديميات وسناتر
> في أكثر من دولة وبأكثر من عملة، وكل مشترك يحصل على منصته الكاملة ببياناته وهويته ونطاقه.

## 14.2 العزل — قاعدة ماستر + قاعدة لكل مشترك

### القرار
`stancl/tenancy` بنمط **Multi‑Database**: قاعدة مركزية + قاعدة مستقلة لكل مشترك.

### قاعدة البيانات المركزية (Central)
```
tenants              id · slug · name · status · plan_id · country · currency
                     locale · timezone · db_name · created_at · trial_ends_at
                     platform_mode · delivery_mode · theme · settings(json)
domains              tenant_id · domain · is_primary · type(subdomain|custom)
                     ssl_status · verified_at
plans                key · name(json) · prices(json per currency) · interval
                     trial_days · is_public · position
features             key · name(json) · type(boolean|limit|quota) · unit · group
plan_features        plan_id · feature_key · value
tenant_features      tenant_id · feature_key · value · expires_at   ← تجاوزات فردية
subscriptions        tenant_id · plan_id · status · period_start · period_end
                     cancel_at · gateway · gateway_ref · retries · next_retry_at
saas_invoices        tenant_id · number · country · currency · subtotal · tax
                     tax_rate · tax_id · total · status · pdf_path · e_invoice_ref
saas_payments        invoice_id · gateway · ref · amount · currency · status
usage_records        tenant_id · feature_key · period · used · limit · updated_at
themes               key · name · modes(json) · version · preview
modules              key · name · version · is_core · default_enabled
tenant_modules       tenant_id · module_key · enabled · settings(json)
super_admins         users المركزيين + الأدوار
impersonations       سجل دخول الإدارة كمشترك (للدعم)
tenant_backups       tenant_id · path · size · created_at · type
audit_central        كل عملية إدارية مركزية
countries            code · name(json) · currency · tax_rate · tax_name
                     gateways(json) · e_invoice_provider · phone_format
currencies           code · symbol · decimals · position · rate · updated_at
```

### قاعدة المشترك (Tenant DB)
كل شيء آخر: `users` (طلاب/مدرّسون/موظفون) · `courses` · `lessons` · `quizzes` ·
`enrollments` · `orders` · `products` · `services` · `bookings` · `posts` · `pages` ·
`center_*` · `settings` · `media` · `notifications` …

### لماذا قاعدة لكل مشترك
| الميزة | التفصيل |
|--------|---------|
| **عزل مطلق** | استحالة تسريب بيانات بين مشتركين — لا `where tenant_id` منسي |
| **نسخ واستعادة فردية** | نسخة احتياطية لمشترك واحد، واستعادتها بلا مساس بالباقي |
| **تصدير كامل** | المشترك يأخذ قاعدته كاملة عند المغادرة — نقطة بيع تسويقية |
| **أداء مستقل** | مشترك ثقيل لا يبطئ الباقي · فهارس أصغر |
| **امتثال** | إمكانية وضع قاعدة مشترك في دولته (متطلب سعودي/إماراتي محتمل) |

### التكلفة والحدود
| البند | الواقع | المعالجة |
|-------|--------|---------|
| MySQL يتحمّل ~2,000–5,000 قاعدة على خادم واحد | حد فعلي | **تقسيم أفقي**: مجموعات خوادم (shards)، كل خادم يحمل N قاعدة، والتوجيه من `tenants.db_shard` |
| الهجرات تُشغَّل على كل قاعدة | ثقيل | `php artisan tenants:migrate` بدفعات عبر الطوابير + تتبّع إصدار لكل مشترك + تشغيل ليلي |
| اتصالات قاعدة البيانات | استهلاك | تجميع الاتصالات (Connection Pooling) + Octane |

### العزل في كل طبقة
```php
Redis        → prefix: tenant_{id}:              (كاش وجلسات منفصلة)
Queues       → payload يحمل tenant_id، والـ Job يبدّل السياق تلقائياً
Storage      → disk خاص: s3://bucket/tenants/{id}/
Search       → فهرس Meilisearch لكل مشترك: {id}_courses
Mail         → مرسل ونطاق المشترك (SPF/DKIM لدومينه)
Broadcasting → قنوات مسبوقة بـ tenant_{id}
Logs         → قناة لكل مشترك للدعم الفني
```

## 14.3 النطاقات و SSL

```
نطاق فرعي (دائماً، لكل الباقات):   ahmed.منصتنا.com
نطاق خاص (حسب الباقة):            academy-ahmed.com
```

**التدفق:**
1. المشترك يضيف نطاقه من لوحته.
2. نعرض له سجل `CNAME` أو `A` المطلوب.
3. تحقّق آلي كل دقيقة (فحص DNS).
4. عند النجاح: إصدار شهادة SSL تلقائياً (**FrankenPHP / Caddy — On‑Demand TLS**).
5. تفعيل النطاق + `canonical` يشير إليه + النطاق الفرعي يصبح `301` عليه (حفاظاً على السيو).

**نطاقات فرعية للنطاق الخاص:** دعم `www` + إعادة توجيه موحّدة + HSTS.

## 14.4 أنماط المنصة (Platform Modes)

المشترك يختارها في معالج التهيئة، **وتُغيَّر لاحقاً بلا فقد بيانات**.

| النمط | لمن | ما يُفعَّل تلقائياً | ما يُخفى |
|-------|-----|-------------------|---------|
| **مدرّس فردي** | مدرّس واحد يبيع كورساته | كورسات · اختبارات · شهادات · متجر · مدونة · تسويق | تعدّد المدرّسين · العمولات · إدارة السنتر |
| **متعدد المدرّسين** | منصة/أكاديمية | + تسجيل مدرّسين · موافقة · عمولات · تحويلات · لوحة مدرّس · تقييمات | إدارة السنتر |
| **سنتر تعليمي** | سنتر أرضي | + فروع · مجموعات · جداول · قاعات · حضور · أقساط · أولياء أمور · خزنة · مصروفات | متجر الكورسات العام (اختياري) |
| **شامل (Hybrid)** | من يجمع الكل | **كل شيء** | لا شيء |

### بُعد ثانٍ: نوع التقديم
`مسجّل` · `مباشر` · `مدمج (Blended)` — يحدد أي حقول ولوحات تظهر في إنشاء الكورس.

### بُعد ثالث: إدارة السنتر
`مفعّلة` / `غير مفعّلة` — مستقلة عن النمط (يمكن لمدرّس فردي أن يدير سنتراً صغيراً).

### ماذا يفعل اختيار النمط فعلياً
```
1. يفعّل مجموعة موديولات محدّدة (tenant_modules)
2. يضبط الإعدادات الافتراضية المناسبة
3. يختار الثيم الافتراضي
4. يبني قوائم لوحة التحكم — يرى ما يخصّه فقط
5. يزرع محتوى تجريبياً قابلاً للحذف (كورس + درس + امتحان نموذجي)
6. يشغّل جولة تعريفية (Onboarding Tour) خاصة بنمطه
```

## 14.5 الباقات والصلاحيات (Entitlements) — العمود الفقري

> **المبدأ:** كل خيار مبني بالكامل في النظام. الباقة والإعدادات هما ما يحدّدان المتاح.

### أنواع المزايا
```php
boolean  → متاح / غير متاح          مثال: center_management, custom_domain
limit    → حد أقصى ثابت              مثال: max_students = 500
quota    → استهلاك دوري متجدّد        مثال: video_minutes/شهر, emails/شهر
```

### الاستعلام في الكود
```php
tenant()->allows('module.center')          // منطقي
tenant()->limit('students')                // 500
tenant()->usage('students')                // 462
tenant()->remaining('storage_gb')          // 3.4
tenant()->overLimit('students')            // false
```

### سلوك تجاوز الحد (متدرّج — لا قطع مفاجئ)
| النسبة | السلوك |
|--------|--------|
| 80% | تنبيه داخل اللوحة + بريد |
| 95% | تنبيه أقوى + اقتراح ترقية |
| 100% | **منع الإضافة الجديدة فقط** — الموجود يبقى يعمل بالكامل |
| تجاوز مدفوع | خيار "تجاوز مؤقّت" يُحاسَب في الفاتورة التالية (قابل للتفعيل) |

**قاعدة مقدّسة:** الطالب الذي دفع لا يُحرم من محتواه أبداً بسبب حد على المشترك.

### عرض المزايا المقفولة
لا تُخفى — تظهر **بقفل + شرح + زر ترقية**. الميزة المخفية لا تُباع.

### قائمة المزايا (~60 مفتاحاً)
```
الحدود:     students · instructors · staff · courses · storage_gb · video_minutes
            live_hours · emails_month · sms_month · whatsapp_month · branches
            groups · admins · custom_reports · api_calls_day

المنطقية:   custom_domain · white_label · remove_branding · custom_css
            multi_instructor · center_management · attendance_devices
            parent_portal · services_module · physical_products · subscriptions
            installments · recharge_codes · affiliates · funnels · email_automation
            whatsapp_api · mobile_app · offline_download · drm · screenshot_block
            device_limit · interactive_video · h5p · scorm · xapi · adaptive_learning
            proctoring · ai_assistant · ai_course_builder · ai_exam_from_pdf
            gamification · community · live_zoom · live_meet · live_bbb · live_jitsi
            page_builder · blog · multi_language · multi_currency · api_access
            webhooks · priority_support · dedicated_db · data_residency
```

### القياس والاستهلاك (Metering)
- عدّادات محدَّثة بالأحداث (لا `COUNT()` لحظي).
- تجميع يومي في `usage_records` + رسم بياني في لوحة المشترك.
- الفيديو والبريد والرسائل تُقاس بالفعل المستهلك لا بالمخزّن.

## 14.6 دورة حياة المشترك

```
تسجيل → تجربة (trialing) → نشط (active)
                              ├─ فشل تحصيل → past_due → (3 محاولات / 7 أيام)
                              │                   ├─ نجح → active
                              │                   └─ فشل → suspended
                              ├─ إلغاء → cancelled (يعمل حتى نهاية الفترة)
                              └─ suspended → (30 يوم) → archived → (60 يوم) → حذف
```

| الحالة | ماذا يحدث |
|--------|-----------|
| `trialing` | كل مزايا الباقة تعمل · بانر بالأيام المتبقية |
| `active` | طبيعي |
| `past_due` | يعمل بالكامل + تنبيه أحمر ثابت + بريد/واتساب |
| `suspended` | **الموقع العام يعمل للطلاب** (لا نعاقب الطلاب) · لوحة المشترك مقفولة عدا صفحة الدفع |
| `cancelled` | يعمل حتى نهاية الفترة المدفوعة |
| `archived` | الموقع مغلق · البيانات محفوظة · تصدير متاح |
| حذف | بعد إشعارات متعددة · مع تصدير نهائي |

**التسجيل الذاتي وبموافقة:** الاثنان مبنيان — إعداد مركزي يحدد (فوري / بموافقة يدوية / بموافقة لدول معيّنة).

## 14.7 التجهيز الآلي (Provisioning)

```
1. إنشاء سجل tenant + اختيار shard
2. إنشاء قاعدة البيانات + تشغيل الهجرات
3. زرع البيانات الأولية حسب النمط المختار
4. إنشاء حساب المدير + كلمة مرور مؤقتة
5. تفعيل الموديولات حسب الباقة والنمط
6. تطبيق الثيم الافتراضي
7. إنشاء النطاق الفرعي + شهادة SSL
8. إنشاء فهرس البحث + مجلد التخزين
9. إرسال بيانات الدخول (بريد + واتساب)
10. تشغيل معالج التهيئة عند أول دخول
```
**الهدف: أقل من 60 ثانية** من الدفع إلى منصة عاملة. (منافسنا `elmanasah` يعد بـ"دقائق" — نحن نستهدف أقل.)

كل خطوة **قابلة للتراجع** (Rollback) عند الفشل، ومسجّلة في `provisioning_log`.

## 14.10 الأمان والعزل

```
□ منع مطلق للاستعلامات عبر المستأجرين — اتصالات منفصلة أصلاً
□ الجلسات والكوكيز مقيّدة بالنطاق
□ رفع الملفات في مساحة المستأجر فقط
□ الطوابير تتحقق من السياق قبل التنفيذ
□ مفاتيح البوابات مشفّرة بمفتاح مشتق لكل مستأجر
□ حدود معدل (Rate limit) لكل مستأجر منفصلة
□ Impersonation يتطلب صلاحية + سبب مكتوب + سجل + إشعار للمشترك
□ اختبار آلي "محاولة تسريب" في CI: مستأجر أ يحاول قراءة بيانات ب → يجب أن يفشل
□ نسخ احتياطي مشفّر لكل مستأجر + اختبار استعادة شهري
```

## 14.11 الأداء والسيو تحت التعدّدية

| التحدّي | المعالجة |
|---------|---------|
| كاش الصفحات لكل نطاق | مفتاح الكاش يتضمّن `host + locale + theme` |
| CDN | تخزين حسب المضيف (Host) |
| تبديل الاتصال يكلّف وقتاً | تجميع الاتصالات + Octane يحتفظ بها حيّة |
| **سيو لكل مشترك** | `sitemap.xml` · `robots.txt` · Schema · `hreflang` · GSC — **مستقلة لكل نطاق** |
| النطاق الفرعي vs الخاص | عند تفعيل الخاص: الفرعي `301` عليه + `canonical` صحيح |
| منع فهرسة المشتركين المعطّلين | `noindex` تلقائي |
| ميزانية الأداء | تُقاس على **عيّنة مشتركين حقيقيين** لا على بيئة فارغة |

## 14.12 التحديثات والإصدارات

- **إصدار واحد للجميع** (لا نسخ متفرّعة لكل مشترك) — وإلا استحالت الصيانة.
- **نشر تدريجي:** ميزة جديدة تُفعّل لـ 5% من المشتركين ثم 25% ثم الكل.
- **هجرات آمنة:** لا تحذف عموداً في نفس الإصدار الذي يتوقف عن استخدامه.
- **نافذة صيانة** لكل shard على حدة — لا توقف كامل.
- **سجل تغييرات** داخل لوحة كل مشترك يشرح الجديد بلغته.
