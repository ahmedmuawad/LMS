# برومت السيشن المحلّية — تشغيل المشروع لوكال + Audit كامل

> انسخ كل ما تحت الخطّ والصقه كأول رسالة في سيشن Claude Code جديدة
> على اللاب توب، بعد `git clone` و`git checkout claude/wplms-courses-services-site-06eek0`.

---

أنت تكمل بناء **منصّة LMS SaaS متعدّدة المستأجرين** بلارافيل، تحلّ محلّ
موقع ووردبريس/WPLMS. المشروع بُني في سيشنات سابقة على السحابة، وأنا
الآن أشغّله **محلّياً على المتصفّح** لأجرّبه بنفسي. مهمّتك في هذه
السيشن ثلاثة أشياء بهذا الترتيب:

1. **شغّل المشروع محلّياً** حتى أفتحه في متصفّحي.
2. **اعمل Audit كامل**: ما أُنجز فعلاً مقابل ما تقوله ملفات التوثيق،
   وما بقي — بلا تجميل.
3. ثم أكمل البنود الناقصة بالترتيب الذي نتّفق عليه بعد الـAudit.

## قواعد العمل (مُلزِمة)

- **العربية** لغة الحوار، وكل نصوص الواجهة والتعليقات في الكود عربية.
- **الفرع**: `claude/wplms-courses-services-site-06eek0`. لا تدفع إلى غيره.
- **لا Pull Request** إلا إن طلبتُه صراحةً.
- **لا Filament ولا إضافات خارجية للسيو أو المدفوعات** — كل شيء داخلي.
- **بلا نسخ مبسّطة**: كل خيار يُبنى كاملاً، ويُحكَم بالإعدادات وبباقة الاشتراك.
- **ديزاين سيستم موحّد** + **ريسبونسيف** + **تباين ألوان سليم على
  الخلفيات الداكنة** — هذه أهم ثلاثة عندي.
- **منهجية العمل**: وثّق ← خطّط ومرحِّل ← نفّذ ← راجع بعينك ← راجع بعين
  **مبرمج آخر** وبعين **صاحب المشروع** ← سُدّ الثغرات ← اقفل المرحلة بتقرير مكتوب.
- **لا تسألني إذناً على كل خطوة** — اشتغل، وأخبرني بالنتيجة.

## أولاً: تشغيل المشروع محلّياً

```sh
composer install
npm ci
cp .env.example .env
php artisan key:generate
touch database/database.sqlite database/testing.sqlite
php artisan migrate --force
npm run build

# مشتركون تجريبيون بأنماط مختلفة
php artisan demo:tenant --fresh                                     # demo.localhost — منصّة متعددة المدرّسين
php artisan demo:tenant --slug=center --mode=center --plan=center --fresh
php artisan demo:tenant --slug=fresh --fresh --onboarding           # لتجربة معالج التهيئة
php artisan super-admin:create --name="المشرف" --email=admin@platform.test --password=<اختر>

php artisan serve --host=127.0.0.1 --port=8000
```

**مهم**: النظام متعدّد المستأجرين بالنطاق الفرعي. أضف إلى `/etc/hosts`
(أو `C:\Windows\System32\drivers\etc\hosts` على ويندوز):

```
127.0.0.1 demo.localhost
127.0.0.1 center.localhost
127.0.0.1 fresh.localhost
```

ثم **جهّز لي جدول حسابات التجربة** وسلّمنيه في الشات: الرابط والدور
والبريد وكلمة المرور لكل حساب، لكل نمط. الحسابات المزروعة اليوم:

| النطاق | البريد | الدور |
|--------|--------|-------|
| `demo.localhost:8000` | `ahmed@example.test` | صاحب المنصّة |
| `demo.localhost:8000` | `nour@t.test` | مدرّس (لوحته محصورة بكورسه) |
| `demo.localhost:8000` | `sara@t.test` | طالبة بتقدّم جزئي |
| `center.localhost:8000` | `ahmed@example.test` | صاحب سنتر |
| `127.0.0.1:8000/super/login` | ما أنشأته أعلاه | مشرف المنصّة |

كلمة المرور الموحّدة للبذرة التجريبية: `password`.

إن فشل أي أمر، أصلحه ولا تكتفِ بالإبلاغ.

اكتب `docs/reports/audit-local.md` يحوي:

1. **جدول لكل ملف توثيق**: ما وعد به · ما وُجد في الكود · الفجوة ·
   دليلها (مسار ملف أو رابط شاشة أو اختبار).
2. **جرد الشاشات كاملاً** من `docs/11-screens-inventory.md`: كل شاشة
   بحالتها — موجودة وتعمل / موجودة ناقصة / غير موجودة — مع مسارها.
3. **فحوص حيّة لا افتراضات**: شغّل الخادم، سجّل الدخول بكل دور، اطرق
   كل رابط في كل قائمة، وسجّل الأكواد الراجعة. لا تقل «تعمل» قبل أن تطرقها.
4. **فحص الأدوار**: جرّب بحساب المدرّس والطالب وولي الأمر وموظّف
   السنتر الوصول إلى شاشات لا تخصّهم، وسجّل أي تسريب.
5. **بوابات المتصفّح**: `node tests/Browser/responsive.mjs` و
   `contrast.mjs` و`behaviour.mjs` و`builder.mjs` على أوسع قائمة
   شاشات ممكنة، وأبلغ بكل فشل.
6. **قائمة أولويات مرقّمة** لما تبقّى، مع تقدير حجم كل بند وسبب ترتيبه.
7. **ما وجدته من أخطاء أو ثغرات لم يذكرها أحد** — هذا أهم قسم.

ثم اعرض عليّ القائمة، وابدأ التنفيذ من أعلاها بعد موافقتي.

## ملاحظات تقنية تختصر عليك الوقت

- `config()` **تقسم المفاتيح على النقطة**: `config('a.b.c')` لا تقرأ
  مفتاحاً حرفياً اسمه `b.c`. اقرأه مصفوفةً: `config('a.b', [])['c']`.
  هذا الخطأ عطّل نظام النقاط والشارات كلّه صامتاً من قبل.
- العربية تحتاج مدى صريحاً في `trans_choice`:
  `{1}…|{2}…|[3,10]…|[11,*]…`.
- اختبارات `tests/Tenancy` لا تستخدم `RefreshDatabase` — تبديل سياق
  المشترك يعيد اتصال القاعدة فتضيع المعاملة. تُهاجَر من الصفر لكل اختبار.
- المتصفّح للفحوص: مرّر `PLAYWRIGHT_CHROMIUM` بمسار كروم عندك، أو
  اتركها فارغة ليستعمل Playwright متصفّحه.
- الديزاين سيستم ثلاث طبقات: أوّليّة `--c-*` ← دلاليّة `--sem-*` ←
  `@theme inline` في Tailwind. **لا تكتب لوناً حرفياً في Blade**.
- الصلاحية اسم ثابت في `app/Core/Access/Ability.php` (قائمة مغلقة)،
  والدور مصفوفة في `config/roles.php`، وحصر الصفوف في
  `app/Core/Access/Scope.php`. **الصلاحية تفتح الشاشة، والحصر يحدّد
  ما فيها — وبغير الثاني تصير الأولى بلا معنى.**
- قائمة اللوحة تشتقّ صلاحية كل عنصر من **حارس مساره نفسه**، فلا تضف
  عنصراً لشاشة غير موجودة: اختبار «لا رابط مكسور» يفشل على أول 404.
